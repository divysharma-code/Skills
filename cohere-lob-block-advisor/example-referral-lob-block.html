Intake · referrals and authorizations

Can we block a referral or an auth by line of business?

Line of business (LOB) means the kind of coverage a member has, such as Commercial, Medicare Advantage or Medicaid. This page shows what the code supports today, what it does not, and who to ask next. Based on a code read of core-platform and frontend on develop, plus the BCBS South Carolina production config you pasted.

The short answer

Authorizations
Partly

A rules-engine redirect rule can turn a member away by LOB. It blocks the member for auths and referrals together. There is no setting in Configuration Management for it.

Referrals only
No

There is no LOB block for referrals. The only gate is a coverage-type list (referralRequiredCoverageType), and it does not turn people away.

The short version, with an analogy

Think of a clinic with two service desks, Auth and Referral, and one guard at the front door.

The guard (the patient search screen) checks each member's badge. The guard can send someone away from the building, so they reach neither desk. The guard cannot say "not the Referral desk, but the Auth desk is fine".

The Referral desk has its own sign: "HMO badges only". Someone without an HMO badge is not turned away. The desk decides a referral is not required and stamps it approved on its own.

Where a block can happen today

Your options

OptionWorks today?What it doesCatch
A. Rules-engine redirect at patient selection, condition on LOB Yes Hides both Start buttons and shows a title and message. Good for "this LOB must not be served here at all". Blocks auths too. Looks frontend-only, so API, fax or internal paths may skip it inferred. Rules are owned by PlatCon and the clinical config team.
B. Tune referralRequiredCoverageType Only if HMO is not shared Lists the product types that need a referral. SC is set to ["HMO"]. Sidnie's worry is that HMO is used for both Medicare Advantage and Commercial. If so, this key cannot tell them apart. One data check settles it (below).
C. New blocked-LOB list in the referral config Needs code Blocks referrals by LOB and leaves auths alone. This is what PCR-749 actually asks for. Intake change. A delegated-vendor config replaces the health plan's whole object, so the list must be copied there too.
D. Replace the auto-approve with a block Needs code Changes the BCBS SC "not required" branch to stop the user instead of approving. Smallest change, but it blocks every product type not listed, not just one LOB.

Setting up option A today

  1. In the rules engine, create a service-request rule for the health plan.
  2. Condition: patient.lineOfBusinessType is one of the LOBs to block. Use lineOfBusinessPayorValue instead for PAI and MEDICARE ADVANTAGE - PDP, which do not match the LOB list the code knows.
  3. Action: Redirect, shown at patient selection, not optional, with a title and message.
  4. Test with one member from each LOB before and after.
